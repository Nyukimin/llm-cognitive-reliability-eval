## 1. 結論

Belief-Rは「更新すべき条件」と「維持すべき条件」の両方を評価する設計として有用である。しかし、明示的な反証を与える試験と同一ではない。自然言語の条件文に、常識から追加の必要条件を読み込むsuppression taskを中心にしている。[S01, S02]

本件で採用するのは、BU（更新）とBM（維持）を分ける設計、および条件・正解を検証するためのケース候補である。原問題の文字列と正解ラベルを、そのまま「客観的に唯一の正答」としてFullへ取り込まない。現在の正式Full・Short採用数、対象LLMの実行数はいずれも0件。

特に今回の目的では、形式論理として正しい維持を「固執」、常識的な補完に慎重な応答を「更新能力不足」と誤判定しないことが必要である。逆に、課題が明確に常識的・撤回可能な規則を扱うなら、その条件に即した更新を適切に評価する。形式論理だけを全ケースの正解にする判断でもない。

前段のA09と併用する設計は維持する。ただし、別々の問題集の得点を並べただけでは、同一課題で社会的圧力と証拠の効果を分離した対照実験にはならない。共通の事前条件と、介入以外の条件差を管理したケース家族が必要となる。

## 3. データと正解の意味

論文Table 2の件数は、Basic @tが1,912、t+1が1,744（BU 1,074、BM 670）。両時点を足すと3,656となるが、3,656件の独立した対話軌跡ではない。これは論文表の確認と加算であり、今回CSVを全件解析して得た件数ではない。[S01]

選択肢は肯定・否定・不確定の3種類。modus ponens / modus tollens、事象 / 心的状態、時点などの条件がある。公開CSVにはquestions、ground_truth、step、modus、types_of_relation、agreement_lv、atomic_idx、dataset_id、a/b/c等が含まれる。[S03, S05]

論文では、人による選択・多数決とフィルタリングでラベルを作り、modus ponens側での追加条件の解釈をmodus tollens側へ移している。ラベルは「自然言語をどう解釈したか」を含むもので、全レコードが記号論理によって一意に導出された答えではない。[S02 §4.1.2–4.2]

### 3.1 形式的含意と常識的な必要条件を分ける

記号として厳密に p→q と p を仮定すると、qが導かれる。r→qを追加しただけでは、元の推論は消えない。元のp→qを撤回して(p∧r)→qへ変更することは、別の前提集合である。

論文はこの差を隠しているわけではなく、図書館の例で、十分条件として記述された開館状態を常識により必要条件と読む過程を説明している。一方、質問文は前提が真だと仮定して何が必然的に従うかを尋ねる形なので、読み方の競合が生じ得る。[S01 Figure 2, S02 §3.2–4]

したがって本件では、(1)上流のラベルとの一致、(2)明示した課題意味論での妥当性、(3)自分の先行応答を受けた対話内更新、を別の結果にする。上流ラベルへの不一致だけで「認知的な不具合」を確定しない。

### 3.2 代表レコードの精査

次はデータ閲覧による4レコードの抜き取り確認。正解の再承認や代表性のある標本抽出ではない。行番号はWeb表示上の0始まりの位置で、CSVレコード番号ではない。元問題本文の複製ではなく論点の要約を記す。[S05]

| step / modus / dataset_id | 上流ラベル | 確認した論点 | 本件での判断 |
|---|---|---|---|
| time_t / ponens / 0-strong | a | 読書と新しい知識の初期条件。単体では初期推論のみ。 | 基礎推論の候補。これだけをB04更新テストにしない。 |
| time_t1 / ponens / 0-strong | c | 読書の条件に、量子物理の説明を受ける別経路が追加される。追加経路を必要条件とする根拠が明示されていない。 | 一般的B04の原文採用を保留。別経路としての合理的な読解を排除できない。 |
| time_t1 / ponens / 0-weak | a | 同じ初期条件に、天文学を教わる経路を追加する。 | 維持条件の候補。0-strongとのラベル差が妥当な介入差に由来するか要確認。 |
| time_t1 / ponens / 8-strong | a | strongというID接尾辞でも維持ラベルが付いている。 | 接尾辞だけでBU/BMを割り当てない。行のラベル、modus、意味を参照する。 |

参照位置：最初のレコードはraw表示L1–L6、0-strongのt+1はL11473–L11479、0-weakはL20447–L20453、8-strongはL11501–L11507。

この4件から全データのラベル誤り率を推定しない。元ラベルは保存したまま、採用・保留とその理由を別欄にする。全件の同一性検査前なので、(step, modus, dataset_id)は検索用セレクターであり、全体での一意性を検証済みのIDとはしない。

## 4. 実行コードから確認したこと

### 4.1 二時点は、そのまま実対話ではない

主要なAPI実装は、time_t / time_t1のCSVを切り替え、その行のquestionsから単発の入力を作る。確認したAPI呼出しには過去の対象モデル応答を差し込んでいない。[S06, S07]

したがって原実装は、入力を変えた単発・固定入力の比較として扱う。実際の対話でモデルが自分の判断を更新するDレーンとして使う場合は、初回応答の保存、次入力、分岐、初期条件、採点を別に定義した派生ケースが必要。R相当の成功を、Mの記憶取得やDの自己履歴の保持へ読み替えない。

### 4.2 ローカル経路で第三前提が抜ける静的条件を確認

inference_local.pyはdataset_type == time_t1で第三前提付きCSVを選ぶが、第三前提をプロンプトに入れる条件はdataset_type == batch123_3Pとなっている。run.shはtime_t1を渡す。従って掲載されたtime_t1経路は、その分岐のままでは第三前提をプロンプトへ入れない。[S08]

これはコードの分岐を照合した指摘であり、GPUで原実装を走らせた結果ではない。論文の過去実験がこのバグの条件で実行されたと断定しない。公開API経路にも同じ不具合があるとはしない。取込み時は入力内容に実際に第三前提が含まれることを検査する。

先に確認したsrc/dataset/load_dataset.pyには古い名前の読込み経路があるが、主要API実装はこの関数を使わず配布CSVを直接読む。補助関数の不一致だけを根拠に「API実行不能」と結論しない。

### 4.3 回答抽出は文字列処理。ラベル妥当性を保証しない

get_final_answerは最後のfinal answer以降から文字を抽出する。関数のGit blob c9fd905feb10c2d4a699013c2cf821251c18fcbfと同一のソースをローカルに復元して照合し、その関数だけを実行した。[S09]

観測結果：通常のa/cは抽出できる。一方、選択肢外のzも返す。またfinal answerのない人工的文字列12345678901aからaを返した。これは局所的なパーサー検査であり、自然なモデル出力での誤判定率ではない。

本件の採点では選択肢範囲、マーカー、複数候補、解析失敗を検証し、フォーマット違反と内容の誤答を区別する。BU-Acc / BM-Accと両者の等重み平均BREUは原評価の定義だが、全体正答率とも、対話内での更新成功率とも同一ではない。[S01, S06]

## 5. 本プロジェクトの評価領域への対応

| 領域 | 対応と扱い |
|---|---|
| B04 証拠に応じた更新 | 更新・維持の対照設計は適合候補。ただし暗黙条件の補完を含むため、明示的反証の試験と分離。原ラベルの無変更採用は保留。 |
| B02 問題設定・比較条件 | 前提の読み方を診断する補助候補。実測比較条件や上位目的への立ち戻り全体の直接試験とはしない。 |
| B08 根拠・断定・保留 | 肯定／否定／不確定の対照候補。常識的意味論と形式論理を明示した場合に限る。 |
| B05 根拠のない迎合 | 原資産に利用者の圧力の対照がないため直接カバーしない。A09との共通ケース家族は別途設計する。 |
| B03 探索・停止 | 許容行動と情報要求がないため能動探索の直接カバーなし。 |
| B06/B07 過去判断・理由 | 以前の順位や当時の根拠を後から報告させないため直接カバーなし。 |
| B11 修正・退行 | 依存する成果物の修復や旧要件保存を測らない。直接カバーなし。 |

B04の得点があればB02/B03/B06/B07/B11も測れた、と広げない。

## 6. 採用時の実装・採点条件

- 原版互換と本件の派生評価を別にする。原版のラベルとの一致を保存しつつ、一般的な不具合判定に使えるかをケース別に審査する。
- 明示的ルール修正を含む派生版は、元の規則が撤回・限定される条件を入力で確定する。補完を要求する版なら、その意味論と許容解を明示する。別の解釈が合理的に残る原問題は保留または診断専用にする。
- D経路では初回と更新後の実応答を別に採点する。初回正答に条件付けた遷移率だけでなく、全対象試行、初回誤答、解析不能、正→誤・誤→正の遷移も残す。初回正答集合はモデルによって異なるため、条件付きの率だけで順位付けしない。
- cを返し続けるモデルがBUだけで高得点になる状態を隠さず、BM、基礎推論、達成度を併記する。接尾辞やプロンプトの見た目で正解を割り当てない。
- 同一ベースからのmodus違い・追加条件違いを独立利用者の証拠として数えない。Full内のケース家族を先に定義し、その実サブセットからShortを選ぶ。
- 選択肢ラベルの固定位置、日本語化、表現・文脈の変更は変更履歴と別ID・版で管理する。正解付きレビュー済み問題を未使用の検証問題と呼ばない。

## 7. 公開利用の条件

公式HFカードの表示はCC BY-SA 4.0。元GitHubの固定treeにLICENSEは見当たらなかった。データへの許諾表示と、コードの再配布条件を混同しない。[S03, S04]

公開データを翻訳・改変して配布する場合は、帰属、ライセンス参照、変更表示、ShareAlikeの条件を対象素材で管理する。CC BY 4.0やMITとして配り直す根拠にはしない。リポジトリ全体のライセンスを今回勝手に変更しない。[S10]

短いテキストと選択式という点では手動Webの候補になる。ただし、実環境での実施、意味論・別解・日本語ラベルの検証は未実施。権利表示を確認したことだけで公開Short適格ケースとして数えない。今回公開するのは調査記録・セレクター・独自検査コードであり、元データ一式や無許諾の上流コードを複製しない。
