# Q01 A17 MTRAG-UN：公開範囲と確認質問Judgeの一次精査

確認日：2026-09-21。状態：B14を中心とするケース供給元・対照設計の条件付き候補。正式Fullへのケース採用、対象モデルの実測、公開再配布の承認ではない。

## 1. 判断

MTRAG-UNは、回答不能、指定不足、前の会話なしでは解釈できない質問、前の応答についての確認という四つの条件を区別する。本件のB14には特に有用だが、確認文を生成したことだけで「必要な確認を適切に選んだ」と採点しない。[S01,S02]

優先するのは、同じ表面的な質問でも、先行情報の有無によって確認すべき場合と答えるべき場合が変わるケースの精査である。履歴の省略、日本語化、対象モデル自身との実対話への変更は派生ケースとして扱う。元の問題を丸ごとFullへ入れない。

## 3. 方式とラベルの意味

論文の生成評価は、既存会話から対象ターンを選び、そこまでの履歴と資料を与える方式である。Reference条件は参照資料が選ばれた後の回答を測る。本件ではRレーンとして扱い、対象モデルがその先行応答を自分で生成したDレーンや、製品固有のMemory取得と同一視しない。[S01,S02]

検索評価とReference生成は分離する。論文は468件の回答可能・部分回答可能な質問を検索評価の対象とするが、これは全生成タスク数ではなく、今回の実測分母でもない。質問の書換えによる検索改善を、モデル自身が競合仮説を比較するB03の能動探索成功へ読み替えない。[S02]

UNclearは、ユーザーが前の応答を理解できない、または異議を持って確認を求める場面を指す。単に「モデルの答えが誤り」というラベルではない。過去の説明を確認することと、過去の自分の判断を現在へ合わせて改変するB06/B07も別である。

回答不能では資料不足の認識、指定不足では意図の特定に必要な確認などを区別する。論文は、欠けた条件の指摘、複数の解釈や選択肢の提示も説明している。一律に疑問文の有無だけを正解にしない。

## 4. 確認質問Judgeの観測限界

`format_underspecified_judge` は `row['inquiry']` を読むが、テンプレートへ渡す変数は `response` だけである。元の質問、先行履歴、参照資料はこのJudge入力に含まれない。プロンプトは無関係な確認を除外すると書いているが、その関連性を照合する元入力がない。[S04]

次のような対照では、同じ回答でも妥当性が異なる。

- どのプランか不明な質問に「どのプランですか」と確認する。
- プラン名が明示された質問に、同じことを聞き直す。

実行した局所検査では、プラン・都市・用語の3対すべてで、異なる質問と資料に対して全く同じJudgeプロンプトが生成された。回答を変えた正常対照ではプロンプトも変わり、改変ソースと回答欠落の負例は拒否された。保存した結果は [A17_local_checks.json](../../data/q01/A17_local_checks.json)。

これは情報がJudgeへ渡らないことの再現検査であり、Judgeが実際に誤判定した結果や誤判定率ではない。公開データの全ラベルや論文の報告精度を否定するものでもない。既存の狭い「確認を求めたか」検出と、本件で必要な「その確認は適切か」を分ける。

`get_idk_underspec_score` は指定不足条件で確認検出の値を優先する。従って別の品質指標が存在するだけで、この不足が自動的に補われるとはしない。[S05] 原採点の互換再現と、本件の意味判定は別の版・指標として管理する。

## 5. 本件の対応と必要な採点

| 領域 | 対応と限界 |
|---|---|
| B14 指定不足・確認 | 強い候補。必要確認、不要確認、許容された仮定・選択肢提示を対照にする。回答だけのJudgeは正式採点へ直採用しない |
| B08 回答保留 | 回答不能と部分回答の区別の候補。検索失敗と資料内の回答不能を区別する |
| B09 資料忠実性 | 履歴・資料と応答の整合の候補。引用支持や出所の独立性全体を測定済みとしない |
| B10 情報利用 | Reference読解と検索経路を別々に評価。非公開の取得状態から内部原因を推定しない |
| B01 目的保持 | 文脈解決は隣接するが、上位目的保持全体の直接測定とはしない |
| B02/B03/B06/B07/B11 | この資産で中核の不足が埋まったとは認定しない |

採点側には現在有効な要求、先行発言、提供資料、候補となる意図、当該応答を与える。必要な確認で課題が未完了でもB01を自動失敗にせず、確認しただけで他の既知要件違反を免除しない。

対象モデルへは課題で許された履歴・資料だけを渡し、gold target、answerability等の採点注釈、スコアを漏らさない。元ファイルの全JSONを無選別にプロンプトへ貼らない。先行発言として許された履歴と、現在ターンの正解を分離する。

同じ会話や元資料に由来する派生問題を独立した利用者・根拠として重複集計しない。入力や注釈の配置・表記は実データとアダプターで照合し、未知値を既定の成功/失敗ラベルへ変換しない。

## 6. 公開・手動経路

リポジトリのLICENSEはApache-2.0である。[S08] ただし参照文書は複数の元コーパスから来ているため、取り込む箇所の出所・適用条件を個別に確認する。リポジトリの表示を理由に、すべての転載文書の権利確認まで完了したとはしない。今回、問題本文や文書コーパスは当方の公開リポジトリへ複製していない。

Reference条件は資料を添えた手動Web試験の候補になる。全コーパスの索引構築を全参加者に必須とする必要はない。ただし履歴・資料の長さ、完全投入、出力採取は未検証であり、手動実施確認済みケースは0。実検索を省いて検索能力を測れたとは報告しない。日本語化や短縮はFull側の派生ケースとして受入れ、その後に同一ケースをShortへ抽出する。
